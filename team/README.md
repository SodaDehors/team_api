# 部署交接说明

## 已配置的参数

| 项目 | 默认值 |
|---|---|
| 应用镜像 | `ghcr.io/wei-shaw/sub2api:0.2.19`，可在 `.env` 改版本 |
| 运行模式 | `simple`，跳过站内余额扣费；不是增加上游额度 |
| 用户总数 | 不限制，不自动创建占位成员 |
| 新成员默认并发 | 1；可改 `.env` 或后台；已有用户需在后台调整 |
| 上游账号总并发 | 接入账号时先填 2，这是初始建议，需按实际限流调整 |
| Key 用量窗口限制 | 启用支持；各 Key 的金额窗口需后台显式填写，0 表示不限制 |
| 初始监听 | `127.0.0.1:8080` |
| 时区 | `Asia/Shanghai` |
| 数据库/缓存 | PostgreSQL 16、Redis 7，均只在容器内部可访问 |
| 持久化 | 三个 Docker 命名卷，普通停止不删除数据 |
| 日志 | 每个容器最多 3 个 10MB 日志文件 |
| 注册与支付 | 首次登录后执行 `configure` 关闭 |

## 首次初始化

在仓库根目录执行 `python3 team/team.py init --admin-email 你的管理员邮箱`。
数据库密码、Redis 密码、JWT 密钥、双因素加密密钥和管理员密码分别随机生成。
不指定邮箱时生成仅用于登录的 `.invalid` 邮箱，不具备收信功能。

实际配置保存在 `team/.env`，已加入 Git 忽略。服务器应重新运行 init，生成自己的密码。
重复 init 会保留旧配置，不会覆盖密码。需要修改参数时编辑 `.env` 后重新 start。
管理员初始化参数仅在首次建库时生效；之后修改密码请走后台，验证脚本使用的 `.env` 也需同步。

## 启动及检查

```sh
python3 team/team.py validate
python3 team/team.py start
python3 team/team.py check
python3 team/team.py status
```

`check` 验证健康接口、管理员登录、认证资料和 simple 模式，不调用任何收费模型。
`configure` 必须在管理员完成项目自身的首次使用确认之后运行；不会代替管理员进行确认。
如果本地管理员启用了验证码或双因素登录，可在网页手动完成设置；自动登录检查不支持交互式验证。

## 给团队提供访问

同机反向代理转发至 `127.0.0.1:8080` 即可，流式响应需禁用缓冲并保留长连接。
采用 Nginx 时按上游说明在 `http` 段设置 `underscores_in_headers on;`。
API Base URL 使用反向代理地址并以 `/v1` 结尾。

仅在内网直接访问时，可初始化为：

```sh
python3 team/team.py init --admin-email 你的管理员邮箱 --bind-host 0.0.0.0
```

已有 `.env` 时直接将 `BIND_HOST` 改为服务器的内网 IPv4 地址或 `0.0.0.0`，然后重新 start。
服务器防火墙只允许团队网络访问该端口；外部接入配置 HTTPS。
成员地址使用服务器的实际内网地址，例如 `http://192.168.1.20:8080/v1`，不要使用成员电脑的 localhost。
成员各用自己的 Key，不分发管理员密码或上游授权。

## 账号和成员由部署方配置

1. 首次登录后运行 `python3 team/team.py configure`。
2. 后台账号管理接入 OpenAI 上游，完成账号持有人授权，设置初始账号并发为 2。
3. 将上游绑定到所需 OpenAI 分组。
4. 按实际成员新增用户；每人创建独立 Key 并绑定分组。人数随时增减。
5. 根据后台显示的可用模型进行一次真实请求，检查流式输出和用量记录。

订阅授权不会开放官方全部模型和接口；可用范围由账号权益和上游行为决定。
仓库内没有真实账号，交接仓库后不会自动获得模型调用能力。

## 停止、升级和备份

```sh
python3 team/team.py logs
python3 team/team.py stop
```

stop 会移除本项目的容器和网络，保留命名卷。不要使用 `down -v`，那会删除数据库等持久数据。
升级前备份 PostgreSQL、应用数据卷及本地 `.env`，尤其要保留加密密钥。
不要只复制数据库所在目录；数据库需使用 pg_dump 或在停库后做一致性备份。
修改 `.env` 的 `SUB2API_IMAGE` 后运行 start，先在测试环境验证新版本。

本地验证环境和服务器分别生成密码与数据卷；交接只发送仓库，不发送本地 `.env` 或数据库数据。
